# C组提交前校验清单

## 分类体系

- [ ] 三类标签 ID 均唯一。
- [ ] 标签 ID 未因改名而重新编号。
- [ ] 每个标签都有定义、正向信号、排除信号和状态。
- [ ] 相邻标签边界能够解释。
- [ ] 所有 active 标签均可由允许的输入字段判断。

## 分类 Prompt 与测试

- [ ] Prompt 明确要求只依据输入，不得补写事实。
- [ ] Prompt 只输出约定 JSON，不输出额外段落。
- [ ] 至少有 10 条测试输入。
- [ ] 每条测试运行 3 次并记录。
- [ ] 所有输出 ID 均存在于 taxonomy。
- [ ] 低置信度或信息缺失时能够请求人工确认。

## 视觉规则

- [ ] 所有规则都有唯一 `rule_id`。
- [ ] 所有标签引用均使用 ID。
- [ ] 存在且仅存在一个 `R-DEFAULT`。
- [ ] 精确、二维、单维和全局降级路径至少各测试一次。
- [ ] `product_ratio` 均在 0 至 1 之间。
- [ ] `info_density` 和 `promotion_intensity` 均为 1 至 5 的整数。
- [ ] 所有 hex 色值格式有效。
- [ ] 所有 active 规则引用的案例 ID 均存在。

## 案例库

- [ ] case ID 唯一，JSON、图片和索引编号一致。
- [ ] 每个 approved 案例来源链接真实可打开。
- [ ] 未使用 AI 生成图片冒充市场案例。
- [ ] 来源、采集日期、使用状态、整理人和审核人完整。
- [ ] 本地案例路径存在；远程案例地址有效。
- [ ] 每条高频精确规则至少有 1 个种子案例。
- [ ] 风格分析具体，不使用空泛套话。

## 用户画像

- [ ] 每个主要 audience 至少有一份 active 画像。
- [ ] 所有 audience 和 scenario ID 均存在。
- [ ] 五项关注权重之和为 1。
- [ ] 文件中没有评分阈值、Loop 或停止规则。

## 交付包

- [ ] JSON 文件均可正常解析。
- [ ] JSONL 每行都是独立合法 JSON。
- [ ] CSV 使用 UTF-8，含逗号的文本已使用双引号包裹。
- [ ] 没有自行增加同义字段或改变冻结字段名。
- [ ] `CHANGELOG.md` 已记录数据版本和修改内容。
- [ ] `待确认问题.md` 已填写；没有问题时写“无”。
